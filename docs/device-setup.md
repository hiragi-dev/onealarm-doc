# 機器のセットアップ

音を鳴らす側の機器を使えるようにする手順。この機器をエッジデバイスと呼ぶ。アプリ側の設定は[はじめかた](/getting-started)を先に済ませておく。

なお、機器とアプリはまだ実際につないで確認できていない。ここに書いた手順や設定値は今後変わることがある。

## 用意するもの

- Raspberry Pi … 音を鳴らし続ける小さなコンピューター
- スピーカー … Raspberry Pi の音声出力につなぐ
- インターネット接続 … 有線でも無線でも構わない
- 配布ファイル … `eager-alarm-edge_*.deb` という名前のファイル。配布時に渡す

置き場所はベッドから離れたところにする。手の届く所に置くと意味がない。電源とネットワークにはつないだままにしておく。

## ① ターミナルの準備

以降はターミナルで作業する。文字を打ってコンピューターに命令する画面のこと。

Raspberry Pi にキーボードとモニターをつなぎ、画面の中の「ターミナル」を開く。別のパソコンから操作する方法は準備中で、配布時にあわせて案内する。

以降のコマンドは、枠の中をそのままコピーして貼り付け、Enter キーを押すだけでよい。

## ② ソフトのインストール

渡された `.deb` ファイルを置いたフォルダで、次を実行する。

```sh
sudo apt install ./eager-alarm-edge_*.deb
```

配布ファイルを機器に取り込むコマンドで、この1回で電源を入れると自動で動き出すところまで終わる。

なお、この時点ではまだつながらない。接続先が未設定のため5秒ごとに接続を試して失敗を繰り返すが、害はなく、次の③で直る。

## ③ 接続先の設定

アプリと機器の連絡を中継するブローカーへの接続情報を書く。

```sh
sudo nano /etc/eager-alarm-edge/env
```

nano という、設定ファイルを編集する画面が開くので、中身を配布時に案内した値に置き換える。

- `MQTT_HOST` … ブローカーのアドレス。配布時に案内する
- `MQTT_PORT` … `8883` のまま変えない
- `MQTT_CLIENT_ID` … `pi` のまま変えない
- `MQTT_USERNAME` … ユーザー名。配布時に案内する
- `MQTT_PASSWORD` … パスワード。配布時に案内する

書き終わったら Ctrl キーを押しながら O を押し、Enter で保存してから、Ctrl キーを押しながら X で閉じる。

```sh
sudo systemctl restart eager-alarm-edge
```

新しい設定を読み込ませるため、機器のソフトを再スタートする。

## ④ 音の設定

```sh
sudo eager-alarm-edge setup
```

音の設定メニューが開く。矢印キーで選び、Enter で決定する。

- サウンドデバイス選択 … どのスピーカーから鳴らすかを選ぶ
- 音量設定 … 0から100で指定する。初期値は80
- 音源選択 … 鳴らす音を選ぶ。何もしなければ内蔵の音になる
- アラームテスト … 実際に音を1回鳴らして確認する

必ずアラームテストまで行い、離れた部屋でも聞こえる音量かを確かめておく。音量や音源の変更は、再スタートしなくてもすぐ反映される。

## ⑤ 動作確認

```sh
systemctl status eager-alarm-edge
```

機器のソフトが動いているかを表示する。緑の `active (running)` と出ていれば正常。

```sh
journalctl -u eager-alarm-edge -f
```

こちらは動作の記録をその場で流し続けるコマンドで、止めるときは Ctrl キーを押しながら C。

最後に、アプリの「設定」タブを開いて図の線とチップが緑になっていれば接続できている。図の見方は[画面の使い方](/screens#settings)に書いている。

## アプリの設定値との対応

アプリの「設定」タブに入れる値と、③で書いた値は次のように対応する。

- ブローカーの URL … 書き方は違うが、`MQTT_HOST` と同じブローカーを指す
- ブローカーのユーザー名 … `MQTT_USERNAME` と同じ値
- ブローカーのパスワード … `MQTT_PASSWORD` と同じ値
- エッジデバイスのデバイスID … 機器側は現在 `pi` で固定

機器側のデバイスIDが `pi` 固定なので、アプリの「デバイスID」もそれに合わせる。ここがずれているとアプリの操作が機器に届かない。同じ理由で、今のところ機器は1台だけで使う。同じ設定の機器を2台置くと、どちらにも同じアラームが入ってしまう。

## そのほか

- 電源の入れ直し … 何もしなくても、起動時に自動で動き出す
- 更新 … 新しい `.deb` を②と同じコマンドで入れるだけ。設定はそのまま残る
- 取り外し … `sudo apt remove eager-alarm-edge` で止められる

## うまくいかない場合

- 音が鳴らない … ④のアラームテストで音が出るか確認する。スピーカーの接続と電源も確認する
- アプリに「エッジデバイスがオフラインです」と出る … 機器の電源とネットワーク、③の入力内容を確認する
- コマンドを打っても何も起きない … 打ち間違いの可能性が高い。もう一度コピーして貼り直す

それでも直らないときは[よくある質問](/faq#connection)も参照。
