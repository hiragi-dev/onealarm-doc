# 機器のセットアップ

音を鳴らす側の機器（**エッジデバイス**）を使えるようにする手順です。
アプリの設定は [はじめかた](/getting-started) を先に済ませてください。

::: warning まだ開発中です
機器とアプリはまだ実際につないで確認できていません。
ここに書いた手順や設定値は、今後変わることがあります。
:::

## 用意するもの

| もの | 補足 |
| --- | --- |
| **Raspberry Pi** | 音を鳴らし続ける小さなコンピューターです |
| **スピーカー** | Raspberry Pi の音声出力につなぎます |
| **インターネット接続** | 有線・無線どちらでも構いません |
| **配布ファイル**（`eager-alarm-edge_*.deb`） | こちらからお渡しします |

::: info 置き場所
**ベッドから離れた場所**に置いてください。手の届く所に置くと意味がなくなります。
電源とネットワークにつながったままにしておいてください。
:::

## ① 機器の画面を出す

以降は **ターミナル**（文字を打ってコンピューターに命令する画面）で作業します。

Raspberry Pi にキーボードとモニターをつなぎ、画面の中の「ターミナル」を開いてください。
別のパソコンから操作する方法は**準備中**です。配布時にあわせてご案内します。

以降のコマンドは、**枠の中をそのままコピーして貼り付け、Enter キーを押す**だけです。

## ② ソフトを入れる

お渡しした `.deb` ファイルを置いたフォルダで、次を実行します。

```sh
sudo apt install ./eager-alarm-edge_*.deb
```

配布ファイルを機器に取り込みます。この1回で、**電源を入れると自動で動き出す**ところまで終わります。

::: info この時点ではまだつながりません
接続先が未設定のため、5秒ごとに接続を試して失敗を繰り返します。害はありません。次の③で直ります。
:::

## ③ 接続先を書き込む

アプリと機器の連絡を中継する **ブローカー** への接続情報を書きます。

```sh
sudo nano /etc/eager-alarm-edge/env
```

設定ファイルを編集する画面（nano）を開きます。

中身を、お伝えする値に置き換えてください。

| 行 | 書く値 |
| --- | --- |
| `MQTT_HOST` | ブローカーのアドレス（お伝えします） |
| `MQTT_PORT` | `8883` のまま変えません |
| `MQTT_CLIENT_ID` | `pi` のまま変えません |
| `MQTT_USERNAME` | ユーザー名（お伝えします） |
| `MQTT_PASSWORD` | パスワード（お伝えします） |

書き終わったら **Ctrl キーを押しながら O** → **Enter** で保存し、**Ctrl キーを押しながら X** で閉じます。

```sh
sudo systemctl restart eager-alarm-edge
```

新しい設定を読み込ませるため、機器のソフトを再スタートします。

## ④ 音を設定する

```sh
sudo eager-alarm-edge setup
```

音の設定メニューを開きます。矢印キーで選び、Enter で決定します。

| メニュー | 何をするか |
| --- | --- |
| **サウンドデバイス選択** | どのスピーカーから鳴らすかを選びます |
| **音量設定** | 0〜100 で指定します（初期値は 80） |
| **音源選択** | 鳴らす音を選びます（何もしなければ内蔵の音） |
| **アラームテスト（1回再生）** | **実際に音を出して確認します** |

必ず **アラームテスト** まで行い、**離れた部屋でも聞こえる音量か**を確かめてください。
音量や音源の変更は、再スタートしなくてもすぐ反映されます。

## ⑤ 動いているか確かめる

```sh
systemctl status eager-alarm-edge
```

機器のソフトが動いているかを表示します。緑の **active (running)** と出ていれば正常です。

```sh
journalctl -u eager-alarm-edge -f
```

動作の記録をその場で流し続けます。止めるときは **Ctrl キーを押しながら C** です。

最後に、アプリの **「設定」** タブを開いて、図の線と丸が緑になっていれば接続できています（→ [画面の使い方](/screens#設定)）。

## アプリの設定値との対応

アプリの「設定」タブに入れる値と、③で書いた値は次のように対応します。

| アプリの「設定」タブ | 機器側の設定 |
| --- | --- |
| ブローカーの **URL** | `MQTT_HOST` と同じブローカー（書き方は異なります） |
| ブローカーの **ユーザー名** | `MQTT_USERNAME` と**同じ値** |
| ブローカーの **パスワード** | `MQTT_PASSWORD` と**同じ値** |
| エッジデバイスの **デバイスID** | 機器側は現在 **`pi` 固定** です |

::: danger デバイスIDは `pi` にしてください
機器側は今のところデバイスIDが `pi` で固定されています。
アプリの「デバイスID」もそれに合わせてください。ここがずれていると、**アプリの操作が機器に届きません。**

また、この固定のため **1台だけ**でお使いください。同じ設定の機器を2台置くと、どちらにも同じアラームが入ります。
:::

## そのほか

- **電源の入れ直し** … 何もしなくても、起動時に自動で動き出します
- **更新** … 新しい `.deb` を②と同じコマンドで入れるだけです。設定はそのまま残ります
- **取り外し** … `sudo apt remove eager-alarm-edge` で止められます

## うまくいかないとき

| 症状 | 確認すること |
| --- | --- |
| 音が鳴らない | ④の **アラームテスト** で音が出るか。スピーカーの接続と電源も確認してください |
| アプリが「エッジデバイスがオフラインです」と出る | 機器の電源とネットワーク、③の入力内容を確認してください |
| コマンドを打っても何も起きない | 打ち間違いです。もう一度コピーして貼り直してください |

それでも直らないときは [よくある質問](/faq#つながらない) を確認してください。
