# 機器のセットアップ

音を鳴らす側の機器(エッジデバイス)を使えるようにする手順です。アプリ側の設定は[はじめかた](/getting-started)を先に済ませておいてください。

注意点として、機器とアプリはまだ実際につないで確認できていません。ここに書いた手順や設定値は今後変わることがあります。

## 用意するもの

- Raspberry Pi … 音を鳴らし続ける小さなコンピューターです
- スピーカー … Raspberry Pi の音声出力につなぎます
- インターネット接続 … 有線・無線どちらでも構いません
- 配布ファイル(`eager-alarm-edge_*.deb`) … こちらからお渡しします

置き場所はベッドから離れたところにしてください。手の届く所に置くと意味がないですね。電源とネットワークにはつないだままにしておきます。

## ① 機器の画面を出す

以降はターミナル(文字を打ってコンピューターに命令する画面)で作業します。

Raspberry Pi にキーボードとモニターをつなぎ、画面の中の「ターミナル」を開いてください。別のパソコンから操作する方法は準備中で、配布時にあわせてご案内します。

以降のコマンドは、枠の中をそのままコピーして貼り付け、Enter キーを押すだけです。

## ② ソフトを入れる

お渡しした `.deb` ファイルを置いたフォルダで、次を実行します。

```sh
sudo apt install ./eager-alarm-edge_*.deb
```

配布ファイルを機器に取り込むコマンドで、この1回で電源を入れると自動で動き出すところまで終わります。

ちなみに、この時点ではまだつながりません。接続先が未設定のため5秒ごとに接続を試して失敗を繰り返しますが、害はなく、次の③で直ります。

## ③ 接続先を書き込む

アプリと機器の連絡を中継するブローカーへの接続情報を書きます。

```sh
sudo nano /etc/eager-alarm-edge/env
```

設定ファイルを編集する画面(nano)が開くので、中身をお伝えする値に置き換えてください。

- `MQTT_HOST` … ブローカーのアドレス(お伝えします)
- `MQTT_PORT` … `8883` のまま変えません
- `MQTT_CLIENT_ID` … `pi` のまま変えません
- `MQTT_USERNAME` … ユーザー名(お伝えします)
- `MQTT_PASSWORD` … パスワード(お伝えします)

書き終わったら Ctrl キーを押しながら O → Enter で保存し、Ctrl キーを押しながら X で閉じます。

```sh
sudo systemctl restart eager-alarm-edge
```

新しい設定を読み込ませるため、機器のソフトを再スタートしています。

## ④ 音を設定する

```sh
sudo eager-alarm-edge setup
```

音の設定メニューが開きます。矢印キーで選び、Enter で決定します。

- サウンドデバイス選択 … どのスピーカーから鳴らすかを選びます
- 音量設定 … 0~100 で指定します(初期値は 80)
- 音源選択 … 鳴らす音を選びます(何もしなければ内蔵の音)
- アラームテスト(1回再生) … 実際に音を出して確認します

必ずアラームテストまで行って、離れた部屋でも聞こえる音量かを確かめておいてください。音量や音源の変更は、再スタートしなくてもすぐ反映されます。

## ⑤ 動いているか確かめる

```sh
systemctl status eager-alarm-edge
```

機器のソフトが動いているかを表示します。緑の `active (running)` と出ていれば正常です。

```sh
journalctl -u eager-alarm-edge -f
```

こちらは動作の記録をその場で流し続けるコマンドで、止めるときは Ctrl キーを押しながら C です。

最後に、アプリの「設定」タブを開いて図の線とチップが緑になっていれば接続できています([画面の使い方](/screens#settings)を参照)。

## アプリの設定値との対応

アプリの「設定」タブに入れる値と、③で書いた値は次のように対応します。

- ブローカーの URL … `MQTT_HOST` と同じブローカーです(書き方は異なります)
- ブローカーのユーザー名 … `MQTT_USERNAME` と同じ値
- ブローカーのパスワード … `MQTT_PASSWORD` と同じ値
- エッジデバイスのデバイスID … 機器側は現在 `pi` で固定されています

注意点として、機器側のデバイスIDが `pi` 固定なので、アプリの「デバイスID」もそれに合わせてください。ここがずれているとアプリの操作が機器に届きません。同じ理由で、今のところ機器は1台だけでお使いください。同じ設定の機器を2台置くと、どちらにも同じアラームが入ってしまいます。

## そのほか

- 電源の入れ直し … 何もしなくても、起動時に自動で動き出します
- 更新 … 新しい `.deb` を②と同じコマンドで入れるだけです。設定はそのまま残ります
- 取り外し … `sudo apt remove eager-alarm-edge` で止められます

## うまくいかないとき

- 音が鳴らない … ④のアラームテストで音が出るか確認してください。スピーカーの接続と電源も見てみてください
- アプリが「エッジデバイスがオフラインです」と出る … 機器の電源とネットワーク、③の入力内容を確認してください
- コマンドを打っても何も起きない … 打ち間違いだと思います。もう一度コピーして貼り直してください

それでも直らないときは[よくある質問](/faq#connection)もご覧ください。
